# 2026-11-19 SUSFS guard LKM v2.6.0 分析与 /data/local/tmp 规则核验

## 结论

- 下载的 `SUSFS_guard_LKM_v2.6.0(9).zip` 是社区 SUSFS guard LKM 模块，**没有安装**。
- 它的 SUSFS 内核本体与 M6Shell 自带的 6.1 guard LKM **完全同一文件**：
  - `kernels/susfs_guard_lkm-android14-6.1.ko` md5 `777e3ba06c70f0ae92460a3700003fbb`
  - M6Shell `assets/susfs_guard_lkm.bin` md5 同上
  - `susfs_insmod` md5 `1216044e4f2549b19389510efdcfc5a8`
  - vermagic `6.1.166-dirty`，description `SUSFS guard LKM (susfs_guard_lkm) v2.3.0-gki`
- 包内 v2.6.0 是**模块封装版本**，不是 SUSFS 内核版本；core 仍是上游 `inforcqb/susfs4ksu-for-lkm` v2.3.0-r18.9-1。
- 下载模块的差异在于：8 个内核分支、`gate` 符号闸门/自检/防变砖、`ksu_susfs` 与完整隐藏规则、开机持久化；M6Shell 只带 6.1 分支并只负责加载 LKM，规则由管理器下发。

## 实机核验

设备：BVL-AN16，内核 `6.1.157-android14-11-g84ffa64b710b`，FinaSU 管理器。

- 模块：`kernelsu 385024 2 - Live (E)`，`getenforce=Enforcing`
- `kgo.31739.log`：`resolved 117/117`、`init_module(... params "expose_proc=1")`、`OK`、`proc_node=1`
- `deploy.log` 的 `SUSFS：sysfs=1 node=0` 是 adb shell（uid 2000）的视角；root 终端读取 `/proc/susfs_path` 已确认：

```text
hide_from_apps=1
path=/data/local/tmp  dev=265289758 ino=131 name=tmp
```

因此 `/data/local/tmp` 的 SUSFS 隐藏规则已生效。`hide_from_apps=1` 只对 App 生效，shell/root 可见属正常；新增规则即时写入内核，不需要重启或软重启。

## 兼容性/风险

- 6.1 分支 .ko 按 `6.1.166-dirty` 编译，目标内核 `6.1.157-android14-11-g84ffa64b710b`；本次能加载靠 `susfs_insmod` 解析符号和修 vermagic，换内核/换 boot 后必须重新验证。
- 目标机 `CONFIG_MODULE_SIG_FORCE=y`；`susfs_insmod` 不签名，能加载不代表其他内核也能加载。
- 下载模块未安装，未改动 boot/镜像；本次没有新增持久化模块。
