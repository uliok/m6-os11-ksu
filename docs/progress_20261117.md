# 2026-11-17 SELinux 全量 access 过滤（春秋 Native check-Eros v4.6.3 通过）

## 症状

- DirtySepolicy 2.2 已经是 `OK: no dirty sepolicy found`，但春秋 Native check-Eros v4.6.3 仍报：

  ```
  检测SELinux Policy时发现可疑问题
  检测到可疑 SELinux 上下文/规则关键词：dsp_bypass system_server/self scrubbed verdict
  ```

- 无 root 时没有这一项，确认是 root 侧策略/查询痕迹，不是荣耀 stock 策略自带。
- 软重启后一度出现 `do-pol v=-2`：`/sys/fs/selinux/policy` 的 fake 页没挂上，但 `do-done` 仍是 1（当时只要求 context/access/policy 任意一个成功）。

## 根因

1. 旧的 pair / 整字清零方案能骗过 DirtySepolicy 的单条 access 查询，但春秋在 **app_zygote / raw selinuxfs** 上做多通道交叉校验：
   - sentinel context 的正控/负控/文件控制
   - raw `/sys/fs/selinux/access` 的 `avdSeqNo`
   - raw 与 libselinux 结果 + 扰动/重复性
   - `system_server/self`、`ksu_file`/`lsposed_file` 等根规则探测
2. `do-done` 的判定条件太宽：context/access 成功就把 policy 的 `-ENOENT` 盖掉，rehook 又只看 context，policy 一直没重试。
3. `ksu_fix_seqno()` 对单字符 `avdSeqNo=2` 直接 return（`delta <= 0` 被当成已经是 1）。

## 修复

- `ksu_fops_ours()` 同时检查 `context` / `access` / `policy` / `status`，任一未挂上就每 5s 重跑 `ksu_fops_do()`。
- `ksu_fops_patch_policy()` 增加「已经是我们副本」判断，避免 rehook 把 `orig` 指回自己造成 read 递归。
- `ksu_fix_seqno()` 单字符分支也写 `'1'`。
- **全量 access 过滤**：`my_write_access_auto` 先走原内核 write，然后用 `backup_sepolicy`（KernelSU 注入前的 stock 策略）：
  - `security_context_to_sid_with_policy(backup_sepolicy, scon/tcon, ...)`
  - `security_compute_av_user_with_policy(backup_sepolicy, ssid, tsid, tclass, &avd)`
  - 把响应覆盖成 `%x %x %x %x %u %x`，`avd.seqno = 1`
  - 未知 context 返回 `EINVAL`（和出厂策略「没这个类型」一致）
  - `backup_sepolicy` 不可用时才回退到旧的 pair 清零
- 只影响 userspace probes；内核内部 `security_compute_av`/AVC 不动，root 自身照常工作。
